# 循迹小车 —— 2026 DEBUG 实验室软件组考核(大部分代码是ai写的)

## 当前实现

- 上电显示四项中文主菜单，默认选中第一项。
- K1 上移、K2 下移、K3 进入、K4 返回；首尾循环选择。
- LED 子菜单：K1 切换两灯常亮/常灭；K2 每 500ms 交换两灯亮灭；K4 返回并关闭两灯。
- 信息页：Liuzehua、32601231、变量 a（上电为 0）。
- USART1 接收有符号 32 位整数，支持 `GET A` 查询；所有页面都能处理串口命令。命令带不带换行都行（空闲 200ms 自动断句），`GET A` 不区分大小写、容忍首尾空格。
- 「巡线功能」页：K1 重放电机自检（L298N 驱动，六步各 1.5 秒）；K2 开始/停止巡线（跟踪五路数字循迹模块：位置加权 + 内轮防卡死下限 + 丢线 1.5 秒停车）；K4 停止并返回；屏幕显示 5 探头实时状态。
- 修复 OLED 长字符串坐标回绕、非法行号、截断 UTF-8 读取；修复中文字库字形。
- OLED 通信出错后终止本次刷新；每秒重新探测并初始化；探测失败时先执行 I2C 总线自恢复（拉最多 9 个时钟 + 补 STOP + 重新初始化 I2C1）再重试一次；**巡线运行期间暂停重初始化**，停车后一拍内恢复。

拓展子菜单只有入口与未实现说明。巡线控制已实现并通过主机模拟测试（五路数字模块，2026-10-05 校准完成），**上赛道实跑验证与调参待做**。

## 接线

以下按原工程假设：STM32F103C8T6 最小系统板（可直插面包板，也可插在套件自带“STM32 扩展板”上）、PC13 低电平点亮的板载 LED、支持 3.3V 供电的 SSD1306 128×64 四针 I2C OLED（7 位地址 0x3C）。模块引脚按丝印名称连接，不按排针左右位置猜测；扩展板上每个信号针旁都有丝印（如 `PB6`、`PA10`），按丝印找针。

| 器件端 | 单片机端 / 接法 |
|---|---|
| OLED VCC | 3.3V |
| OLED GND | GND |
| OLED SCL / SCK | PB6 |
| OLED SDA | PB7 |
| K1 | 一端 PB12，另一端 GND |
| K2 | 一端 PB8，另一端 GND |
| K3 | 一端 PB14，另一端 GND |
| K4 | 一端 PB15，另一端 GND |
| LED1 | 使用板载 PC13 LED，无需外接 |
| LED2 | 3.3V → 1kΩ 电阻 → LED 阳极；LED 阴极 → PB5 |
| USB-TTL TXD | PA10（单片机 RX） |
| USB-TTL RXD | PA9（单片机 TX） |
| USB-TTL GND | GND |
| ST-Link SWDIO | PA13 |
| ST-Link SWCLK | PA14 |
| ST-Link GND | GND |
| ST-Link NRST（可选） | NRST / RST |

### 电机与电源（L298N，2026-09-27 起使用）

| L298N 端子/引脚 | 接到 | 说明 |
|---|---|---|
| `12V`（电源端子） | 电池盒红线（6V） | 电机主电源 |
| `GND`（电源端子） | 电池盒黑线 **+ 单片机 GND** | 必须与单片机共地 |
| `5V`（电源端子） | 不接 | 板载 5V 使能跳线保持插着 |
| `输出A` | 左电机两根线 | 螺丝压紧 |
| `输出B` | 右电机两根线 | 螺丝压紧 |
| `ENA` | PA0（TIM2_CH1，10kHz PWM） | 拔掉板上的 ENA 跳线帽 |
| `IN1` | PA2 | 方向 |
| `IN2` | PA3 | 方向 |
| `IN3` | PA4 | 方向 |
| `IN4` | PA5 | 方向 |
| `ENB` | PA1（TIM2_CH2，10kHz PWM） | 拔掉板上的 ENB 跳线帽 |

原 TB6612 方案的 `STBY`（PA6）已停用。2026-09-29~10-05 期间 PA6/PB10/PB11 曾用作八路模拟循迹模块的通道选择线，随该模块（判硬件损坏）一并退役；**现 PB10/PB11 为五路数字模块的 M/L1 输入**（见下）。L298N 有约 1.5~2V 压降，6V 电池供电时电机端电压约 4V，属正常现象。

> 电机方向排查：**前进/后退反了** → 把该电机两根线在端子内的**顺序对调**；**左右转向反了**（前后正常）→ 把两组电机线在 `输出A`/`输出B` 之间**整组对调**（组内顺序别动）。

### 循迹传感器（五路数字，2026-10-05 起使用）

| 模块丝印 | 接到 | 说明 |
|---|---|---|
| `VCC` | **5V** | 模块按 5V 设计（3.3V 下实测阈值卡死、全部不响应）；信号脚 PA8/PB9/10/11/13 均为 5V 容忍引脚 |
| `GND` | GND | 与单片机共地 |
| `L2` | PB13 | 数字输出：**白底=0，黑线=1** |
| `L1` | PB11 | 数字输出 |
| `M` | PB10 | 数字输出（中间探头） |
| `R1` | PA8 | 数字输出 |
| `R2` | PB9 | 数字输出 |

板上 5 个电位器需**逐路校准**：垫黑胶带于对应探头下方，边拧电位器边看 OLED 上的 5 位实时状态，找到"能翻"区间后**停在区间中部**——拧过头会进入"恒 0 / 恒 1"卡死区间（现象：垫什么都不变），必须回调到响应区。2026-10-05 五路全部校准完成，标准：**白=0、黑=1**。

### （已淘汰）循迹传感器 YB-MVX05 八路灰度（2026-09-29 期间使用）

> 该模块最终**判定硬件损坏**（证据链见"2026-09-29 排查结论"），已换用上面的五路数字模块；接线记录保留备查。

| 模块丝印 | 接到 | 说明 |
|---|---|---|
| `5V` | 3.3V | （历史）OUT 是模拟量，5V 供电会超出 ADC 量程 |
| `GND` | GND | |
| `AD0` | PB10 | 通道选择（数字输出） |
| `AD1` | PB11 | 通道选择（数字输出） |
| `AD2` | PA6 | 通道选择（数字输出） |
| `OUT` | PB1（ADC1_IN9） | 8 路探头经 4051 模拟开关汇成的单路模拟输出 |

> **PA6 不能做模拟输入**（2026-09-29 实测 + 底板原理图确认）：板载 4 位数码管是共阳管，阳极经 R2 接 3.3V，段 a~g / dp 直接接 PA0~PA7；挂在 PA6 上的 g 段 LED 会把该引脚钳在约 2.3V，传感器信号根本进不来（读数恒为 ~2.28V、黑白无反应）。PB1 在底板上没有连接任何其他电路。

按键已启用内部上拉，不需要外接上拉。四脚轻触按键应先用万用表确认“松开不通、按下导通”的两脚，避免接到内部一直相通的两脚。

USB-TTL 使用 **3.3V 逻辑电平**；串口适配器的 VCC 在主板已经独立供电时不接。主板可按其说明通过 USB 供电，所有模块共地。不要将 5V 接到主板 3.3V 引脚。ST-Link 若有 VTref/VAPP 电压检测端，接主板 3.3V；该端不应一律当作供电输出，具体按调试器标识与说明连接。

OLED 的 SDA/SCL 必须有上拉至 3.3V。常见模块已带上拉，先确认；如果没有，可各加约 4.7kΩ 上拉并使用短线，如 400kHz 下波形不佳需按总线电容调整电阻或降低速率。若你的屏幕是 SH1106、SPI 接口或地址为 0x3D，本版配置不能直接套用。

MCU 引脚复用与供电范围参考：[ST STM32F103x8/xB 数据手册](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)。本工程保持内部 HSI 8MHz 时钟，不依赖外部晶振。

## 串口操作

参数：**9600 baud，8 数据位，无校验，1 停止位，无流控；文本/ASCII 发送**。

每条命令可以以回车或换行结束（CR、LF、CRLF 都可）；**不带换行的单条命令同样支持**——收到最后一个字节后 200ms 内没有新字节就自动按一条命令处理（适配默认不勾选“发送新行”的串口助手）。下表中的 `\r\n` 表示真实回车换行，不是输入反斜杠字母。

| 发送 | 返回 | 结果 |
|---|---|---|
| `111\r\n` | `OK\r\n` | a = 111 |
| `GET A\r\n` | `111\r\n` | 查询当前值 |
| `-25\r\n` | `OK\r\n` | a = -25 |
| `0\r\n` | `OK\r\n` | a = 0 |
| `2147483648\r\n` | `ERR\r\n` | 越界，保持原值 |

合法范围：-2147483648 到 2147483647。`GET A` 不区分大小写、允许首尾空格。建议每发一条等待回复再发下一条；超长行、非法字符、接收溢出会被丢弃，不把残缺数据写入 a。发生串口溢出后先发一个空行重新同步，再发送命令。

## 固件健壮性修复：I2C 总线自恢复（2026-09-26）

- **问题**：`HAL_I2C_*` 在超时路径下不一定发出 STOP，I2C 外设可能停留在 BUSY；原来的重试逻辑只重新探测屏幕、不复位总线，因此干扰消失后仍会持续失败（现象：画面冻结、按键其实有效但屏幕不刷新）。
- **修复**：新增 `I2C1_RecoverBus()`（`main.c` 的 USER CODE 4）。探测失败时把 PB6/PB7 暂时当作普通开漏 GPIO：最多打 9 个时钟脉冲直到从机释放 SDA → 补一个 STOP → 恢复 AF 配置 → 重新 `MX_I2C1_Init()`。`OLED_Init()` 第一次探测失败后调用它并重试一次。编译 0 错误 0 警告，上板验证通过（`oled_ok` 实测为 1，屏幕正常显示菜单）。
- **定位方法**：临时诊断固件对所有 GPIO 引脚**两两组合**做软件 I2C 扫描（避开 SWD 的 PA13/PA14），并输出每个引脚的“内部下拉读位”上拉图。实测结果：模块在 PB6/PB7、地址 0x3C 应答、初始化与整屏写入全部成功 —— 用于在线路混乱时快速定位 SCL/SDA 到底落在哪一列。
- **第二次黑屏的接线复查**：SCL 仍未真正落到 PB6（插在旁边的孔里）。最终改为把母头**直接套在针尖上**接好；同轮排查确认四键空闲电平、串口与 LED 均正常。

## 更新（2026-09-29）：评审问题修复（巡线阻塞 / 串口错误帧 / 测试补桩）

- **巡线页分页刷新**：原实现每 250ms 整屏刷新一次（400kHz 下约 23ms），期间 5ms 转向循环停摆。新增 `OLED_RefreshStart()/OLED_RefreshStep()`：一次只推一页（约 3ms），穿插在控制循环中，8 页铺满一帧；菜单页仍走阻塞式整屏刷新。
- **串口错误帧空闲断句**：`discard_line` 置位后（收到非法字节 / 超长行 / 接收溢出），原来只有换行才会结算，导致后续"不带换行"的命令被永久吞掉。现在 200ms 空闲断句同样结算错误帧（回 `ERR` 并复位），可继续正常收发。
- **主机测试补桩并加用例**：`Tests/test_app.c` 补上 `Motor_*`、`Track_*`、`I2C1_RecoverBus` 的桩；新增用例：分页刷新逐步推送/错误中断、总线恢复只调一次、巡线启动与转向（含内轮防卡死下限）、丢线 1.5s 停车、串口非法字节与溢出后的无换行命令恢复。`Tests/run.ps1` 全绿。
- 编译（ARMCLANG 6.18）：0 错误 0 警告。
- **评审第二轮修复（同日）**：
  - **串口空闲断句加固**：改为"接收队列已全部读完 + 关中断快照（时间戳与队列状态一致）"才判定，错误帧只结算一次。修掉两个复现问题：① 40 字节积压被 32 字节预算截断后过早结算 → 尾部 `11111111` 被当成新命令写入变量；② 接收中断恰好落在两次读取之间导致无符号时间差回绕 → `123` 被拆成 `12` + `3`。
  - **OLED 恢复路径拆分**：`OLED_Init()` 末尾由阻塞整屏刷新改为 `OLED_RefreshStart()`（分页推送）。巡线中每秒重探测不再出现"单次 App_Tick 60 次同步 I2C 传输"的阻塞；恢复帧由巡线循环分页补齐。
  - **ADC 采样状态独立返回**：`adc_read()` 返回成功/失败；任一次转换失败即该次扫描报 `mask=0` / `pos=NO_LINE`（低电平识线模式下不会再出现"全部采样失败却得到居中"），巡线逻辑按丢线处理并在超时后停车。
  - **主机测试再升级**：`track.c` 作为真实翻译单元参与编译（假 HAL 提供 ADC 与多路选通跟踪），新增用例：>32 字节积压的断句、ADC 故障（含低电平模式）、巡线中 OLED 重初始化的传输上限（<40）。`Tests/run.ps1` 全绿，Keil 0 错误 0 警告。
- **评审第三轮修复（同日）**：巡线期间**暂停 OLED 重初始化**——探测失败时不再每秒重试（两次同步 `IsDeviceReady` 在总线卡死时各可能等满超时，单次主循环可阻塞约 50ms）；K2/K4/丢线停车后一拍内自动恢复。用例实测：巡线中掉线 + 4 个探测窗口**整拍零 I2C 流量**、面板保持断开，停车当拍完成重初始化。另：总线死在半页刷新时，`oled_ok=0` 使分页步骤立即变空操作，阻塞上界收紧到单次失败传输的 ≤10ms。

## 更新（2026-10-05）：五路数字循迹模块 + 巡线固件改写 + 校准完成
