## 当前实现

- 上电显示四项中文主菜单，默认选中第一项。
- K1 上移、K2 下移、K3 进入、K4 返回；首尾循环选择。
- LED 子菜单：K1 切换两灯常亮/常灭；K2 每 500ms 交换两灯亮灭；K4 返回并关闭两灯。
- 信息页：Liuzehua、32601231、变量 a（上电为 0）。
- USART1 接收有符号 32 位整数，支持 `GET A` 查询；所有页面都能处理串口命令。
- 修复 OLED 长字符串坐标回绕、非法行号、截断 UTF-8 读取；修复中文字库字形。
- OLED 通信出错后终止本次刷新，每秒尝试重新初始化。

巡线、拓展子菜单只有入口与明确的未实现说明。目前没有电机、传感器、蜂鸣器控制，不能据此进行小车赛题完整验收。

## 接线

以下按原工程假设：STM32F103C8T6 最小系统板、PC13 低电平点亮的板载 LED、支持 3.3V 供电的 SSD1306 128×64 四针 I2C OLED（7 位地址 0x3C）。模块引脚按丝印名称连接，不按排针左右位置猜测。

| 器件端 | 单片机端 / 接法 |
|---|---|
| OLED VCC | 3.3V |
| OLED GND | GND |
| OLED SCL / SCK | PB6 |
| OLED SDA | PB7 |
| K1 | 一端 PB12，另一端 GND |
| K2 | 一端 PB8，另一端 GND |
| K3 | 一端 PB14，另一端 GND |
| K4 | 一端 PB15，另一端 GND |
| LED1 | 使用板载 PC13 LED，无需外接 |
| LED2 | 3.3V → 1kΩ 电阻 → LED 阳极；LED 阴极 → PB5 |
| USB-TTL TXD | PA10（单片机 RX） |
| USB-TTL RXD | PA9（单片机 TX） |
| USB-TTL GND | GND |
| ST-Link SWDIO | PA13 |
| ST-Link SWCLK | PA14 |
| ST-Link GND | GND |
| ST-Link NRST（可选） | NRST / RST |

按键已启用内部上拉，不需要外接上拉。四脚轻触按键应先用万用表确认“松开不通、按下导通”的两脚，避免接到内部一直相通的两脚。

USB-TTL 使用 **3.3V 逻辑电平**；串口适配器的 VCC 在主板已经独立供电时不接。主板可按其说明通过 USB 供电，所有模块共地。不要将 5V 接到主板 3.3V 引脚。ST-Link 若有 VTref/VAPP 电压检测端，接主板 3.3V；该端不应一律当作供电输出，具体按调试器标识与说明连接。

OLED 的 SDA/SCL 必须有上拉至 3.3V。常见模块已带上拉，先确认；如果没有，可各加约 4.7kΩ 上拉并使用短线，如 400kHz 下波形不佳需按总线电容调整电阻或降低速率。若你的屏幕是 SH1106、SPI 接口或地址为 0x3D，本版配置不能直接套用。

MCU 引脚复用与供电范围参考：[ST STM32F103x8/xB 数据手册](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)。本工程保持内部 HSI 8MHz 时钟，不依赖外部晶振。

2. F7 编译；确认 Debug/Utilities 的下载器选择 ST-Link，并使用 SWD。
3. 主板 BOOT0 置 0，连接供电及 ST-Link，F8 下载，然后复位。
4. 上电应看到四项菜单，两个 LED 默认熄灭。

生成文件：`MDK-ARM/diangdeng/diangdeng.hex`。这是面向 STM32F103C8 的固件。

CubeMX 文件已同步 UART 9600、PA9/PA10、USART1 中断及 LED 初始高电平。应用逻辑位于独立的 app.c，main.c 中的调用放在 USER CODE 区。重新生成后仍应检查 Keil 工程包含 app.c、oled.c、oledfont.c、cnfont.c 和 HAL UART 驱动；本次没有实际运行 CubeMX 验证再生成过程。

## 串口操作

参数：**9600 baud，8 数据位，无校验，1 停止位，无流控；文本/ASCII 发送**。

每条命令必须以回车或换行结束（CR、LF、CRLF 都可）。在串口助手中勾选“发送新行/回车换行”。下表中的 `\r\n` 表示真实回车换行，不是输入反斜杠字母。

| 发送 | 返回 | 结果 |
|---|---|---|
| `111\r\n` | `OK\r\n` | a = 111 |
| `GET A\r\n` | `111\r\n` | 查询当前值 |
| `-25\r\n` | `OK\r\n` | a = -25 |
| `0\r\n` | `OK\r\n` | a = 0 |
| `2147483648\r\n` | `ERR\r\n` | 越界，保持原值 |

合法范围：-2147483648 到 2147483647。GET A 区分大小写，不加额外空格。建议每发一条等待回复再发下一条；超长行、非法字符、接收溢出会被丢弃，不把残缺数据写入 a。发生串口溢出后先发一个空行重新同步，再发送命令。

## 硬体验证记录（2026-09-24）

板卡：STM32F103C8T6 最小系统板 + SSD1306 128×64（I2C 0x3C）+ CH340 USB-TTL + 面包板。当天实测：

- OLED：上电显示主菜单，箭头默认第 1 行；I2C 地址 0x3C 实测有应答，屏幕正常点亮。
- 按键：K1/K2 移动箭头、K3 进入子菜单、K4 返回主菜单，四个键实测有效（空闲为高电平、按下变低）。
- LED：LED1（板载 PC13）随 K1 常亮/常灭切换有效。
- 串口：9600 8N1 实测 `123` → `OK`、`GET A` → `123`、`abc` → `ERR`，变量 a 的写入/查询链路正确。
- 调试记录（问题与原因）：
  - OLED 黑屏：SCL 实际没有接到 PB6（面包板插到了别的列）。用 SWD 在线读 `GPIOB_IDR` + 自写位翻转 I2C 扫描程序定位，改接后正常。
  - 按键无反应：轻触按键的两个接线脚用了内部常通的那一对，等于把引脚直接接地。改用"按键两端各一个脚"后正常。
